## Notes

- Peak RAM (Ollama) is the summed working set of the Ollama server and its llama-server runner, which holds the model.
- Peak VRAM is total GPU memory in use (nvidia-smi), including other applications; subtract the idle figure above.
- Model load time is measured once per model before the runs and is not included in analysis time.
- The long document is the clean rental agreement with two renumbered copies of its clauses appended.
- Both models ran with the same extra checks (self-consistency and pairwise, the Thorough settings), so the E2B rows overstate Fast-mode time slightly; Fast mode skips self-consistency.
- Analysis time is roughly flat from medium to long documents because LexLocal sends at most 3 clauses per category to the model; longer documents mainly cost retrieval and rule time, which stays under a second.
- The first run's 'consistency' stage includes loading the embedding model (about 15 s, once per process).
- If 'VRAM in use before the run' is already high, a model was still resident from earlier use, so peak VRAM mostly reflects that resident model. E4B (6.6 GB) does not fit in 4 GB of VRAM and is split with system RAM, which is why its Ollama RAM is several GB.
